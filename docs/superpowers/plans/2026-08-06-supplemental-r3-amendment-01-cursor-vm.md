## Failure Shutdown Contract

The Cursor transcript and a VM-external append-only journal hold command
provenance until terminal publication; ongoing logging must never dirty the
repository between the pre-network seal and the first evidence request. The
fixed journal path is
`/tmp/supplemental-r3-amendment-01-command-journal.jsonl`. Each UTF-8 JSONL
record contains `sequence`, `stage`, `argv`, `started_at_utc`, `ended_at_utc`,
`exit_code`, `stdout_sha256`, `stderr_sha256`, `evidence_request`, and
`runner_state`; sequence is contiguous from 1 and records are fsync-appended
without rewriting earlier bytes. The Cursor transcript is the independent
source for importing bootstrap records before the runner exists. The
injected command runner must record a failure atomically when an invoked
command or invariant first fails. After that transition, its state is terminal
and it rejects every non-shutdown action.

The only permitted post-failure actions are:

1. finalize `FIRST_FAILURE_AMENDMENT_01.json` and
   `COMMAND_LOG_AMENDMENT_01.json` with the first failed stage, exact argv,
   raw exit code, stdout/stderr SHA-256, UTC bounds, completed evidence-request
   count, last successful cursor/page, and confirmation of no partial payload;
2. verify in memory that no published snapshot, queue, decision, candidate
   sheet, evidence manifest, payload, or success handoff was created;
3. if every Task 1 bootstrap assertion passed and no payload commit exists,
   publish and commit only those two diagnostics with path-isolated commit
   semantics, push the new branch once without force, and stop;
4. if any Task 1 assertion fails, write no repository file and perform no
   commit or push; preserve only the already captured Cursor transcript,
   report the failed command/exit, and stop; or
5. once the candidate tree has been atomically published into the repository,
   or if a payload commit already exists, perform no diagnostic file edit,
   commit, or push. Preserve only the fsynced external journal/Cursor
   transcript, report the local commit identities, and stop. An unverified
   payload or handoff history must never be pushed by the failure path.

Temporary raw pages must live outside the repository and may never be
published after failure. Diagnostic finalization is not a retry. No diagnostic
command may enumerate/read refs or objects, contact GitHub evidence endpoints,
change code/tests/contracts, or attempt to improve the outcome.

The diagnostic-only terminal commands are legal only after complete Task 1
bootstrap and before creation of a payload commit. They are exactly:

```bash
python3 scripts/external_slice/supplemental_r3_common.py run-shutdown-and-record --journal /tmp/supplemental-r3-amendment-01-command-journal.jsonl -- git add data/external_slice/supplemental_r3/FIRST_FAILURE_AMENDMENT_01.json data/external_slice/supplemental_r3/COMMAND_LOG_AMENDMENT_01.json
python3 scripts/external_slice/supplemental_r3_common.py run-shutdown-and-record --journal /tmp/supplemental-r3-amendment-01-command-journal.jsonl -- git commit --only data/external_slice/supplemental_r3/FIRST_FAILURE_AMENDMENT_01.json data/external_slice/supplemental_r3/COMMAND_LOG_AMENDMENT_01.json -m "data(external): record supplemental R3 Amendment 01 first failure"
python3 scripts/external_slice/supplemental_r3_common.py run-shutdown-and-record --journal /tmp/supplemental-r3-amendment-01-command-journal.jsonl -- git push -u origin cursor/grok-phase3-supplemental-r3-amendment-01-evidence
```

Each is attempted at most once. `git commit --only` must exclude any pre-staged
code, seal, raw page, payload, or handoff path; the staged-pollution negative
test proves this behavior. If a diagnostic commit cannot be created or the
push fails, do not retry; report the local commit if one exists and stop. A
Task 1 failure after `git switch -c` still follows rule 4: no diagnostic file,
commit, or push, even though the local branch exists. Do not run a diagnostic
probe first.
